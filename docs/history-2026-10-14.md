# История работ за 2026-10-14

## Исходное состояние

- Найден исходный сервис в `/root/web/proxy-service`.
- Исходный forward proxy опубликован на `8890`, admin API — на `8891`.
- Зафиксировано правило: исходный сервис и его контейнер не изменять.
- Рядом обнаружен отдельный, остановленный MTProxy; он к этой работе не относится.

## Создание proxy-v2

- Создана независимая рабочая копия в `/root/web/proxy-service-8880`.
- Для неё создан отдельный контейнер `proxy-service-8880`.
- Назначены внешние порты:
  - `8880` — forward proxy;
  - `8881` — admin API и healthcheck.
- Журнал копии хранится отдельно от журнала исходного сервиса.
- Проверены healthcheck и независимая работа обоих контейнеров.

## Репозитории

- Первоначальный снимок сохранён в приватном репозитории `proxy-v1`.
- Основным remote рабочей копии назначен приватный репозиторий:
  `git@github.com:Yury-mygit/proxy-v2.git`.
- Репозиторий `proxy-v1` сохранён как дополнительный remote `v1`.
- Секреты, `.env`, журналы и `node_modules` исключены из Git.

## Аутентификация

- Proxy-аутентификация переведена на Basic с отдельными переменными
  `PROXY_LOGIN` и `PROXY_PASSWORD`.
- Поддержка Bearer для подключения к proxy удалена.
- Сравнение логина и пароля выполняется через constant-time comparison.
- В RaftForge создан обычный пользователь для proxy-v2.
- Пользователю выдан единственный resource `proxy-v2`; кураторских прав и
  доступа к другим ресурсам нет.
- Локальные proxy-credentials хранятся в игнорируемом `.env.v2` и не
  синхронизируются автоматически при смене пароля в RaftForge.
- Добавлены тесты успешного Basic-входа, неверных credentials и отклонения
  Bearer-аутентификации.

## Запуск и внешний доступ

- Контейнер собран и запущен на `0.0.0.0:8880` и `0.0.0.0:8881`.
- Для внешнего доступа в firewall хостинга требуется входящее правило
  `TCP/8880`. Порт `8881` открывать наружу для пользовательского трафика
  не требуется.
- В Proxifier тип этого HTTP CONNECT proxy отображается как `HTTPS`.
- Успешно проверены HTTP- и HTTPS-запросы с авторизацией через публичный
  адрес proxy.

## IPv6

- Исправлен разбор CONNECT targets формата `[IPv6]:port`.
- Добавлена строгая проверка порта в диапазоне `1..65535`.
- Добавлены регрессионные тесты для DNS-имён, IPv4, IPv6 и ошибочных targets.
- VPS имеет только публичный IPv4 и не имеет default route в IPv6.
- Поэтому прямые IPv6 targets корректно разбираются, но завершаются
  `ENETUNREACH` и ответом `502`.
- Для IPv4-only VPS в Proxifier следует включить разрешение доменных имён
  через proxy. Если приложение всё равно передаёт готовые IPv6-адреса,
  оно обычно повторяет запрос по доменному имени/IPv4; при необходимости
  IPv6 можно отключить на клиентском сетевом адаптере.
- Проверено, что основные Claude/Anthropic endpoints успешно работают по
  доменным именам через proxy; ошибки IPv6 сопровождаются успешным IPv4
  fallback.
